# Fiskta 2.0 — Breaking Changes (Revised)

This document proposes intentional, compatibility-breaking changes to improve Fiskta's public API and CLI for a 2.0 release. This revision removes opaque types and struct versioning in favor of a simpler, more transparent approach.

## Executive Summary
- Clean up the public API by not exporting unnecessary internal headers
- Decouple library error semantics from CLI exit codes
- Expose memory budgets through explicit options (not compile-time macros)
- Tighten CLI flags to remove ambiguity
- Accept that ABI changes are breaking and use semver properly

---

## Public API Surface

### 1) Don't export internal headers from fiskta.h
- **Change**: Remove `#include "engine.h"` and `#include "fileio.h"` from `src/fiskta.h`
- **Impact**: Third-party code that included those headers indirectly must include them explicitly (if needed)
- **Rationale**: Reduces the public surface area; internal types shouldn't leak transitively
- **Action**: Keep `fiskta.h` and `fiskta_types.h` as the public includes; everything else is internal

### 2) Keep Program/Clause/Op structs visible but documented as internal
- **Change**: Keep these structs in `fiskta_types.h` but document fields as internal
- **Impact**: None - structs remain visible for inspection and debugging
- **Rationale**: Transparency aids debugging; we trust C programmers to respect documentation
- **Note**: Direct field access is unsupported; use the API functions

### 3) Library return types should be library errors, not CLI exit codes
- **Change**: Have library entry points return `enum Err` instead of `int`/`enum FisktaExitCode`
- **Impact**: Callers handling exit codes must switch to `enum Err` (CLI continues to map to exit codes)
- **Rationale**: Separates library error taxonomy from CLI policy
- **Action**: Change signatures of `program_requirements`, `build_program`, `runtime_execute`, and `runtime_execute_buffer`

### 4) Hide error_set from public API
- **Change**: Remove `error_set` from `fiskta.h`; keep as internal helper
- **Impact**: External code setting errors directly must stop doing so
- **Rationale**: Setting thread-local error state is an internal concern
- **Note**: Error observation can still happen via return codes

---

## Memory/Budget Configuration

### 5) Make regex budget configurable via options
- **Change**: Add `BuildOptions` struct with `size_t regex_budget_bytes` and `u64 regex_work_budget`
- **Impact**: Function signatures change; callers can tune memory without recompiling
- **Rationale**: Embedders need policy control per program/instance
- **Action**: Pass `BuildOptions` to `program_requirements` and `build_program`

```c
typedef struct BuildOptions {
    size_t regex_budget_bytes;  // 0 = use default
    u64 regex_work_budget;      // 0 = use default
} BuildOptions;
```

### 6) Move regex_work_budget out of RuntimeBuffers
- **Change**: Remove `regex_work_budget` from `RuntimeBuffers`; put it in `BuildOptions` or `RuntimeConfig`
- **Impact**: Call sites setting work budget do so via options
- **Rationale**: It's a policy knob, not part of scratch layout

---

## Type Hygiene

### 7) Prefer size_t for sizes/counts
- **Change**: Use `size_t` for `String.len`, token counts, buffer lengths, and capacities
- **Impact**: Signature and struct changes; supports 2+ GB inputs where practical
- **Rationale**: Aligns with C idioms and removes artificial limits
- **Note**: Use safe overflow checking where needed

### 8) Remove misleading regex hints
- **Change**: Drop `RuntimeRequirements.any_lazy_quantifiers`/`any_counters` (they're always true)
- **Impact**: Consumers relying on these hints need to change
- **Rationale**: Current implementation is misleading; remove rather than fix
- **Alternative**: Compute them correctly during parse if actually useful

---

## Error Reporting

### 9) Don't print from library code by default
- **Change**: Library stops printing to stderr; CLI layer owns printing
- **Impact**: Embedders no longer see unsolicited stderr output; CLI unchanged
- **Rationale**: Logging/printing is an application concern
- **Action**: Move all `fprintf(stderr, ...)` from library code to `main.c`

---

## CLI Behavior

### 10) Make --ops unambiguous
- **Change**: `--ops` is always an inline string; require `--ops-file` for file inputs
- **Impact**: Users relying on autodetection must switch to `--ops-file`
- **Rationale**: Autodetection is ambiguous and hard to reason about
- **Action**: Remove "file if exists" detection logic

### 11) Rename --ignore-failures to --continue-on-fail
- **Change**: Prefer clearer flag name; keep `--ignore-failures` as alias in 2.x
- **Impact**: Scripts continue working in 2.x; plan removal in 3.0
- **Rationale**: Better expresses intent in follow/tail workflows

---

## Symbol/Namespace Hygiene

### 12) Consolidate public symbols with fiskta_ prefix
- **Change**: Keep only `fiskta_*` and `FISKTA_*` public symbols
- **Impact**: Reduces collision risks with other libraries
- **Rationale**: Standard C practice for libraries
- **Action**: Namespace or make static: `io_*`, `regex_*`, `search_*`, internal helpers

---

## Execution Semantics: Document and Freeze

### 13) Line/char navigation semantics
- **Current**: `io_line_start`/`io_line_end` return positions after newline; UTF-8 stepping snaps to code point boundaries
- **Action**: Document as the 2.0 contract and keep stable thereafter

### 14) Regex anchors and CRLF
- **Current**: `^`/`$` treat CRLF as a single line ending when matching at boundaries
- **Action**: Document as 2.0 contract; avoid semantic changes post-2.0

---

## What We're NOT Doing (and Why)

### ❌ Opaque types
- **Rejected**: Making `Program`/`Clause`/`Op` opaque handles
- **Why**: Harms debuggability, adds indirection, conflicts with zero-malloc embedding
- **Instead**: Keep structs transparent; document internal fields

### ❌ Struct versioning
- **Rejected**: Adding `api_version` and `struct_size` fields
- **Why**: False sense of compatibility; doesn't prevent ABI breaks; adds boilerplate
- **Instead**: Accept that struct changes break ABI; use semver major bumps

### ❌ Complex compatibility layers
- **Rejected**: Maintaining multiple version paths and shims
- **Why**: Too much maintenance burden for a small project
- **Instead**: Make clean breaks; users can pin versions if needed

## Migration Notes

### For Library Users

**Return codes**
```c
// Before
int result = build_program(...);
if (result != 0) { /* handle */ }

// After
enum Err err = build_program(...);
if (err != E_OK) { /* handle */ }
```

**Budgets and options**
```c
// Before
// Compile-time macros only

// After
BuildOptions opts = {
    .regex_budget_bytes = 100000,
    .regex_work_budget = 1000000,
};
err = program_requirements(tokens, count, path, &opts, &reqs, &path_out);
```

**Error printing**
```c
// Before
// Library printed to stderr

// After
// Install your own error handler or check return codes
if (err != E_OK) {
    fprintf(stderr, "Error: %d\n", err);
}
```

### For CLI Users

**Operations input**
```bash
# Before
./fiskta --ops program.fisk  # Ambiguous: string or file?

# After
./fiskta --ops "find ERROR take to line-end"    # Inline string
./fiskta --ops-file program.fisk                # File path
```

**Continue on failure**
```bash
# Before
./fiskta --ignore-failures --continue 1s ...

# After (both work in 2.x)
./fiskta --continue-on-fail --continue 1s ...
./fiskta --ignore-failures --continue 1s ...   # Deprecated alias
```

## Versioning Philosophy

We embrace semantic versioning:
- **Major version bump** = Breaking changes (ABI, API, behavior)
- **Minor version bump** = Additive changes (new functions, new flags)
- **Patch version bump** = Bug fixes only

If you need ABI stability, pin to a specific version. We won't try to maintain compatibility layers across major versions.
